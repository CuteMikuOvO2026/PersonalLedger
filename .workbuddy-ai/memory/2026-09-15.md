# 2026-09-15 工作日志

## Bug 修复（第四轮）：选中 pill 右角被切平（用户描述为「屏幕适配做的不好」）

用户反馈「屏幕适配做的不好」，截图（130×85）显示报表页时间筛选 Tab 的选中项「近三个月」。
上一轮的灰影问题已确认修复（截图中 `#41484D` 完全消失，调色板干净）。

### 诊断方法：pill 轮廓的左右角拟合

用 B 通道线性插值算出每个像素的「pill 覆盖率 t」（容器 `#121A21` 的 B=0x21 → pill `#25455C` 的 B=0x5C），
取 t=50% 的穿越点作为边界，逐行得到 pill 轮廓：

```
 y |  pillL   pillR | width
 26 |   35.22   96.20 | 60.98
 27 |   32.50   98.69 | 66.19
 28 |   30.56  100.49 | 69.94
 29 |   29.50  101.49 | 71.99
 30 |   28.50  101.49 | 72.99
 31 |   27.50  101.49 | 73.99
 32 |   26.50  101.50 | 75.00
 34 |   25.50  101.50 | 76.00
 36 |   24.50  101.50 | 77.00   ← 左边界达到极值
 …  |   …      101.50 | …      ← 右边界从 y=29 起恒为 101.50（直线！）
 52 |   29.63  101.49 | 71.86
 55 |   36.82   94.50 | 57.68
```

**关键发现：左角跨越 y=26→36 共 10 行平滑内缩（完整圆角），右角只跨 y=26→29 共 3 行就变成竖直直线。**

### 拟合结果（决定性证据）

| 侧 | 拟合 |
|---|---|
| 左角 | 圆心 x≈40.1，半径 ≈15px，`inset(d)=r−sqrt(d(2r−d))` 与实测逐行吻合（误差 <0.6px） |
| 右角 | 用同一半径 15px 拟合，**要求 drawable 右边界到 x≈107.2**；而可见边缘止于 101.5 |

→ **指示器 drawable 宽约 83px，可见区域仅 77px，右侧约 6px 被裁掉。**

裁剪边界 x=101.5 恰好等于「容器右边缘 104 − 3dp padding」= TabLayout 的内边距边界。

### 根因（反编译 material-1.10.0.aar 确认）

`com.google.android.material.tabs.TabIndicatorInterpolator`：

```java
static RectF calculateIndicatorWidthForTab(TabLayout tabLayout, View tab) {
    if (!tabLayout.isTabIndicatorFullWidth() && tab instanceof TabLayout.TabView)
        return calculateTabViewContentBounds((TabView) tab, 24);
    return new RectF(tab.getLeft(), tab.getTop(), tab.getRight(), tab.getBottom());
}
```

**`tabIndicatorFullWidth=true` 时，指示器边界 = Tab 自身的 left/top/right/bottom。**

而承载 Tab 的 `TabLayout$SlidingTabIndicator`（LinearLayout）会被 TabLayout 的 padding 内缩，
并且会**裁剪超出自身边界的子 View**。

所以只要指示器比内容区宽出一点点，最后一个 Tab 的 pill 右角就被切平。
（同理，第一个 Tab 的左角在「全部」被选中时也会被切。）

### 修复

**核心思路：把内边距从 TabLayout 挪进指示器 drawable，让裁剪边界外移到容器边缘。**

1. **`drawable/bg_tab_indicator.xml`** — 由 `<shape>` 改为 `<layer-list>`，内层 `<item>` 四边各 3dp 内缩。
2. **`values/styles.xml`** — `tabIndicatorHeight` 由「pill 目标高度」改为「TabLayout 完整高度」：
   - `PieRange`：34dp → **40dp**（pill 实际 = 40−3−3 = 34dp）
   - `EntryType`：44dp → **50dp**（pill 实际 = 50−3−3 = 44dp）
   - 基础样式注释新增第 4 条：**使用处禁止给 TabLayout 设 `android:padding`**（附根因说明）
3. **`layout/fragment_report.xml`** — 移除 `android:padding="3dp"`
4. **`layout/bottom_sheet_input.xml`** — 移除 `android:padding="3dp"`

视觉结果不变（pill 距容器边缘仍 3dp、高度仍 34/44dp），但裁剪边界外移 3dp，圆角不再被切。

### 验证（aapt2 全链路）

- `aapt2 compile --dir app/src/main/res` → **rc=0，0 error 0 warning**
- 编译 83 个依赖 AAR 的 `res/` 并全部 `-R` 链接 + `android.jar` → **rc=0，无任何诊断，产出 15.5MB APK**
- `dump resources` 反查确认：`PieRange.tabIndicatorHeight=40dp`、`EntryType.tabIndicatorHeight=50dp`、`bg_tab_indicator` 已编译
- 51 个 XML 全部解析通过（0 失败）

### 关键结论（复用）

- **Material TabLayout 的 `tabIndicatorFullWidth=true` ⇒ 指示器 = Tab 边界**；TabLayout 一旦有 `padding`，
  `SlidingTabIndicator` 的裁剪就会切掉首/末 Tab 的 pill 圆角。
  **正确做法：TabLayout 不设 padding，内缩全部交给指示器 drawable 的 layer-list。**
- **`tabIndicatorHeight` 语义是「指示器 View 的高度」，不是「pill 的最终高度」**。若 drawable 带内缩，
  必须写成 TabLayout 的完整高度。
- **判别「pill 被裁剪」的方法**：逐行求 50% 覆盖率边界，拟合左右角半径。
  若左右角半径不一致（一侧跨 10 行、另一侧跨 3 行），就是被裁了，而不是 drawable 形状问题。
- `TabLayout$SlidingTabIndicator.onMeasure` 里 `tabGravity` 的整型值：**fill=0 / center=1 / start=2**；
  `tabMode`：scrollable=0 / fixed=1 / auto=2。反编译时容易把 `iconst_1` 误读成 GRAVITY_FILL
  （实际是 GRAVITY_CENTER），进而误判分支逻辑——需以 `attrs.xml` 的 enum 值为准。

## Bug 修复（第四轮·续）：溢出未被消除，pill 右角仍被裁

用户再次反馈「问题还是存在，注意图中画圈的位置，展示不完整」（新截图 125×91，红圈套在 pill 右侧）。
复测轮廓：**右角依旧只跨 3 行就变直线**，裁剪边界 x=95.5 = 容器右缘 98 − 3dp，说明上一轮只解决了「裁剪边界」，
**没有解决「Tab 溢出」这个根因**。

### 补齐的根因（反编译 + 实测）

`SlidingTabIndicator.onMeasure` 的首行分支（结合 attrs 的真实枚举值）：

```java
if (tabGravity == GRAVITY_CENTER /* = 1 */) { ...分布/降级... }
else if (mode != MODE_AUTO /* = 2 */) return;   // fill + fixed → 直接 return
```

**所以 `tabGravity=fill` + `tabMode=fixed` 时该方法直接返回**，Tab 完全靠 LinearLayout 的 `weight=1` 均分宽度。

但 **`TabLayout.TabView.onMeasure` 取 `max(测量宽度, 内容宽度)` 作为最终宽度**。
当「文本宽 + tabPaddingStart + tabPaddingEnd」大于均分宽度时，Tab 就会**溢出内容区**，
再被 `SlidingTabIndicator` 裁掉 —— pill 圆角再次被切。

实测（缩放 0.875 px/dp，屏幕约 390dp）：
- 容器 = 313.25px（358dp），内容区 = 308px（352dp），均分宽度 = 77px（88dp）
- 实测 Tab 宽 = 82.65px（**94.5dp**）→ 每个 Tab 溢出 5.65px
- 容器右缘 98，裁剪边界 95.5，drawable 右缘（拟合）101.15

### 补充修复

1. **`values/styles.xml`** — `Widget.PersonalLedger.TabLayout` 新增：
   - `<item name="tabPaddingStart">0dp</item>` + `<item name="tabPaddingEnd">0dp</item>`
     → 内容宽度降到约 56dp，远小于均分宽度 88dp，**溢出从源头消失**
     （fixed + fill 下文本居中，tabPadding 不影响外观）
   - `<item name="tabIndicatorAnimationMode">linear</item>`
     → 去掉 M3 继承来的 `elastic`；elastic 插值器在中途会把指示器拉长（`decInterp`/`accInterp` 不对称），
       也会造成越界裁剪
   - 注释新增第 5 条，记录 tabPadding 与溢出的关系
2. **`drawable/bg_tab_indicator.xml`** — 水平内缩 3dp → **4dp**（垂直仍 3dp），作为兜底余量

### 教训

**修「被裁剪」类问题必须同时处理两件事：① 裁剪边界（谁在裁）② 被裁的内容为什么越界。**
上一轮只改了①（把 padding 挪进 drawable），没查②（Tab 为何比内容区宽），所以问题复现。
另外：**反编译读 `iconst_N` 必须先用 attrs 的 enum 值校准**，否则分支语义会完全理解反
（本轮一开始就把 `tabGravity == 1` 误读成 FILL，绕了一大圈）。
