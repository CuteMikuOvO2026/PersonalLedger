## Bug 修复：TabLayout 选中指示器显示扭曲

用户反馈饼图时间筛选 Tab 的选中项（「全部」）显示异常——背景色块断裂、边缘出现直角缺口。

### 根因

`Widget.PersonalLedger.TabLayout` 中 `tabIndicator` 指向 18dp 圆角的 `bg_tab_indicator`，但调用处又设了 `app:tabIndicatorHeight="0dp"`（原意图是"用 tabBackground 当选中态、不画指示器"）。Material 的 `TabIndicatorView` **用 `tabIndicatorHeight` 作为指示器的 layout height**，且 `tabIndicatorFullWidth=false`（默认）时宽度只按文字测量宽度包住文字。

结果：18dp 圆角的形状被强压到 0 高度，圆角半径无法压缩，在 0 高度下画出残缺弧线；同时指示器宽度与 Tab 宽度不一致，形成视觉断裂。

### 修复方案

**`values/styles.xml`** — 样式拆为三层：
- `Widget.PersonalLedger.TabLayout`：基础样式，去掉写死的 `tabIndicatorHeight`，改为 `tabIndicatorFullWidth=true`（让指示器占满 Tab 宽）+ `tabIndicatorGravity=center`
- `Widget.PersonalLedger.TabLayout.PieRange`：`tabIndicatorHeight=34dp`（报表页：容器 40dp − padding 3dp×2）
- `Widget.PersonalLedger.TabLayout.EntryType`：`tabIndicatorHeight=44dp`（记账弹窗：容器 50dp − padding 3dp×2）

**`fragment_report.xml` / `bottom_sheet_input.xml`** — 两处都删掉 `app:tabIndicatorHeight="0dp"`，改用对应的子样式；`android:background` 从 `@color/surface_container_low` 换成新的 `@drawable/bg_tab_container`（21dp 圆角容器）。

**`drawable/bg_tab_item.xml`** — 从静态矩形改为 **ripple**（带 18dp 圆角 mask）。原来用静态形状覆盖 `tabBackground` 会丢掉 Material3 默认的按压涟漪，改成 ripple 后保留触摸反馈。

**新增 `drawable/bg_tab_container.xml`** — 分段控件的圆角容器底色（`surface_container_low`，随深浅主题自动切换）。

### 关键结论（复用）

- **Material TabLayout 的 `tabBackground` 应该放 ripple drawable，不是静态形状**；静态形状会吞掉按压反馈。
- **`tabIndicatorHeight` 必须等于「TabLayout 高度 − 上下 padding」**，否则指示器会被拉伸或压扁，圆角形状失真。
- `tabIndicatorFullWidth=false`（默认）时指示器宽度按文字包络，分段控件场景应显式设为 `true`，让选中 pill 与 Tab 等宽。
- `bottom_sheet_input.xml` 存在**同类潜在 bug**（同样是 `tabIndicatorHeight="0dp"` + 18dp 圆角指示器），本次一并修复。

## Bug 修复（第二轮）：指示器被 colorPrimary 染色 + 选中态对比度不足

用户反馈修复后"还是不够完美"。逐像素解码截图后定位到**第二个更隐蔽的根因**。

### 根因（关键，务必记住）

**Material3 的 `Base.Widget.Material3.TabLayout` 同时设置了 `tabIndicator` 和 `tabIndicatorColor`，而后者的默认值是 `?attr/colorPrimary`。**

拆开 `material-1.10.0.aar` 的 `res/values/values.xml` 可确认：
```xml
<style name="Base.Widget.Material3.TabLayout" parent="Widget.MaterialComponents.TabLayout">
    <item name="tabIndicator">@drawable/m3_tabs_rounded_line_indicator</item>
    <item name="tabIndicatorColor">@macro/m3_comp_primary_navigation_tab_active_indicator_color</item>  <!-- = ?attr/colorPrimary -->
    ...
```
**结论：只覆盖 `tabIndicator` 而不覆盖 `tabIndicatorColor`，自定义 drawable 的颜色会被 colorPrimary 顶替。** 这正是截图里 pill 显示为亮蓝 `#5FB0E8`（= 深色主题的 `md_theme_primary`）而非 `bg_tab_indicator` 里写的 `surface_chip` 的原因。

### 逐像素诊断证据

截图 108×54，pill 实测为 `#5FB0E8`（= md_theme_primary），而非预期的 surface_chip。
另出现异常色 `#41484D`，其分布为：
- y=9~11 横向 52/62/66px —— 容器未被 pill 覆盖的上边缘
- y=12~34 每行仅 1~7px —— pill 左侧 1px 抗锯齿描边
该色是亮蓝 pill 与深色容器叠加的抗锯齿混色（既不是 surface_container_low 也不是 surface_chip）。

### 修复

1. **`styles.xml`**：`Widget.PersonalLedger.TabLayout` 显式加 `<item name="tabIndicatorColor">@android:color/transparent</item>`，让指示器完全由 `bg_tab_indicator` 的 solid 色决定。
2. **`values/colors.xml`**：`surface_chip` 由 `#DCEBF8` 改为 **`#A5CCEE`**（浅色）。
3. **`values-night/colors.xml`**：`surface_chip` 由 `#1C3040` 改为 **`#25455C`**（深色）。

### 配色选型依据（WCAG 对比度实测）

原 `surface_chip` 太淡：浅色下 pill↔容器仅 **1.11:1**（几乎看不出选中态）。
新值同时满足两个目标：

| 主题 | pill | 容器 | pill↔容器 | pill↔文字 |
|---|---|---|---|---|
| 浅色 | #A5CCEE | #EFF5FA | 1.53:1 | 8.94:1 |
| 深色 | #25455C | #121A21 | 1.74:1 | 8.52:1 |

**副带收益**：`surface_chip` 同时用于底部导航的选中指示器，浅色下可见度由 1.11:1 提升到 **1.68:1**（原本几乎看不见）。

**被否决的方案**：用 `md_theme_primary` 做实心 pill + 白字。实测深色下 pill↔文字仅 **2.62:1**、浅色 4.98:1，未达 WCAG 4.5:1。

## Bug 修复（第三轮）：选中 pill 左上角的灰色"阴影"

用户明确纠正：真正的缺陷是**选中 pill 左侧一圈灰影**（截图中用红圈标出），前两轮都没打到点上。

### 根因（关键，务必记住）

**这个"阴影"根本不是阴影，而是纯白色状态层（state layer），被 TabLayout 按"Tab 的整个矩形"绘制。**

证据链（逐像素解码截图 118×60）：

| 项目 | 实测 |
|---|---|
| 异常色 | `#41484D`（中性灰 65,72,77），216 px |
| 反解三通道 alpha（前景=纯白，基底=容器 `#121A21`） | R=0.19831 / G=0.20087 / B=0.19820 → **三通道一致，前景确定是纯白**，α≈0.20 |
| 若是抗锯齿（pill `#25455C` × 60% + 容器 `#121A21` × 40%） | 理论值 `#1D3444` —— 实测 R=65 远高于理论 R=0x1D，且**蓝色关系被破坏** → 排除抗锯齿 |
| 几何 | 阴影 bbox `x=[17,93] y=[14,39]`；pill 顶边 y=17。**阴影比 pill 高 3px，上沿是整行平直连续** → 按 Tab 矩形绘制，不是 pill 形状 |

来源：`Widget.PersonalLedger.TabLayout` 的父链
`Widget.Material3.TabLayout` → `Base.Widget.Material3.TabLayout` → `Widget.MaterialComponents.TabLayout`，

### 修复

1. **`drawable/bg_tab_item.xml`**：从 ripple **改为纯透明 shape**。分段控件的选中态完全由 `bg_tab_indicator` 的实色胶囊表达，tab 自身不再叠加任何白色层。
2. **`values/styles.xml`** 的 `Widget.PersonalLedger.TabLayout` 新增三项：
   - `<item name="tabRippleColor">@android:color/transparent</item>` —— 从源头掐掉白色状态层
   - `<item name="tabUnboundedRipple">false</item>` —— 禁止越界绘制
   - `<item name="android:stateListAnimator">@null</item>` —— 去掉多余状态动画

### 验证方式（重要：aapt2 离线全链路，可复用）

Gradle 整体编译仍不可用（AGP 9.1.0 plugin marker 缺失），但**资源侧可以用 aapt2 单独完成真实验证**，比 XML 语法检查强得多：

```bash
AAPT="D:/AndroidSDK/build-tools/36.1.0/aapt2.exe"
# 1) 编译 app 资源（0 error 0 warning）
"$AAPT" compile --dir app/src/main/res -o res.zip
# 2) 逐个编译依赖 AAR 的 res/（44 个依赖中 28 个带资源）
"$AAPT" compile --dir <aar解压目录>/res -o lib-<name>.zip
# 3) 链接：-I android.jar + --manifest（需手动补 package 属性）+ 全部 -R libzip
"$AAPT" link -o out.apk -I D:/AndroidSDK/platforms/android-36.1/android.jar \
    --manifest tmp/AndroidManifest.xml --min-sdk-version 24 --target-sdk-version 36 \
    --auto-add-overlay -R lib-*.zip res.zip
```

要点：
- **`link` 时必须给 `-I` 传 `android.jar`，并把所有依赖 AAR 的资源用 `-R` 一起链接**；只给 android.jar 会报几百条 `style/Theme.Material3.* not found`、`attr/colorPrimary not found`（全是缺依赖库资源，不是代码问题）。
- aapt2 直连时 manifest 需要**手动补 `package="com.example.personalledger"`**（AGP 是从 `namespace` 注入的）。
- 本机 platform 目录是 `android-36.1` / `android-37.0`，**没有 `android-36`**，`-I` 要用 `android-36.1/android.jar`。
- 反查最终值：`"$AAPT" dump resources out.apk`，可在资源表里确认样式实际生效。

本轮结果：`link` rc=0，产出 15.1MB APK，`dump resources` 确认
`tabRippleColor=@0x0106000d(transparent)`、`tabUnboundedRipple=false`、`tabBackground=@drawable/bg_tab_item`、`parent=style/Widget.Material3.TabLayout` 全部落地；两个子样式 `tabIndicatorHeight` 分别为 34dp / 44dp。

### 关键结论（复用）

- **Material TabLayout 的 `tabBackground` 不要用 ripple**——分段控件场景下 ripple 的白色状态层会按 Tab 矩形常驻，看起来像一块灰"阴影"。用纯透明 shape，触摸反馈交给 `tabRippleColor`（显式设透明）与文字/指示器变化承担。
- 判断"看起来像阴影的东西"到底是阴影还是叠加层：**反解三通道 alpha 是否一致**。若三通道反解出的 alpha 相同，说明前景是中性色（白/黑/灰）的叠加层；若不一致，才是两种颜色的混色（抗锯齿）。
- 另一个判别法：**真阴影一定比背景暗**（黑色高斯模糊）；实测值比背景更亮 → 必然是浅色叠加层。
